# 企业财税领域知识引擎（先行版）

面向企业财税领域的**可溯源知识问答与方案生成引擎**。

它不是"把一堆 PDF 丢给大模型自由发挥"的问答机器人，而是先把法规整理成**有版本、
有效力、可追溯**的结构化知识，再让检索结果带着出处回答。

## 它解决什么问题

通用大模型回答财税问题有三个致命伤：**编造条文、混淆时效、说不出来源**。
本项目用一条链路把这三件事锁住：

1. **采集**——从官方渠道批量抓取法规原文，保留文号、发文机关、施行日期
2. **结构化**——按 章 / 节 / 条 / 款 / 项 五级切分，抽取税种、效力状态、生效区间
3. **复核**——人工审核放行，未放行的知识一律不进召回
4. **检索**——结构化 + 语义稠密 + 术语稀疏三路召回，RRF 融合后启发式重排
5. **回答**——只引用真实存在的条文，标明法规名称与条号

## 能做什么

| 能力 | 说明 |
|---|---|
| 法规问答 | 口语提问 → 六段式答案（判定 / 依据 / 计算 / 步骤 / 风险 / 说明），每条依据可点开原文 |
| 税费计算 | 独立计算器，增值税与附加税费分步展示；金额走字符串，不丢精度 |
| 筹划方案 | 企业画像 → 多方案对比 → 量化测算；命中红线直接拒绝并给出合规替代路径 |
| 专家复核台 | 🔴 高风险方案只进复核台，放行 / 修改后放行 / 驳回（驳回必须写原因） |
| 政策变化提醒 | 监控官方发布并按影响程度排序；未接入推送通道时如实说明，不假装已发送 |
| 管理后台 | 知识管理、缺口清单、评测报告与门禁结论、审计留痕 |
| 知识库运维 | 采集 / 导入 / 复核 / 修复 / 重建索引，各有命令行脚本 |

> 筹划功能默认关闭（`FEATURE_PLANNING_ENABLED=false`）：向他人提供涉税专业服务需要有
> 资质主体承担，资质落实后再打开开关。

## 关键设计

| 设计 | 解决什么 |
|---|---|
| 效力状态硬过滤 | 已废止、待复核的条文在检索下推阶段就被拦住，不会出现在结果里 |
| 时点查询（as-of date） | 同一问题问"2023 年"和"2025 年"，各自命中当时有效的口径 |
| 条文级版本与生效区间 | 数据库层排斥约束，两个版本的生效区间重叠会被 100% 拒绝 |
| 域包零代码扩展 | 新增领域只需加 `domains/<域名>/` 目录，不改引擎代码（已由测试锁住） |
| 元数据不猜 | 文号、机关、日期抽不到就标记为待复核，绝不编造 |

## 快速开始（4 步）

前提：已安装 Docker Desktop 并**处于运行状态**（任务栏鲸鱼图标不转圈）。

```bash
# 1. 生成环境变量文件（首次，从模板复制）
copy .env.example .env
#    PowerShell 用：Copy-Item .env.example .env

# 2. 启动全部依赖
docker compose up -d

# 3. 看健康状态
docker compose ps
curl http://localhost:8000/api/health
```

`.env` 已加入 `.gitignore`，不会被提交。里面是开发用的占位口令，
生产环境请务必改成自己的密钥（`POSTGRES_PASSWORD`、`JWT_SECRET`、
`S3_ACCESS_KEY` / `S3_SECRET_KEY`）。

完整的分步操作（配置项怎么填、模型怎么下、数据怎么初始化、装完怎么验收）
见 [部署与配置手册](docs/部署与配置手册.md)。

看到 `docker compose ps` 各常驻服务为 `healthy`（建桶任务 `cs_s3_init` 显示 `Exited (0)` 属正常，
它的活干完就退出），且 `/api/health` 返回各依赖 `ok`，环境即就绪。

不想逐个看，就跑一句话自检：

```bash
python scripts\smoke_test.py
```

再补一句对象存储的检查（会验证密钥能不能读写、越权会不会被拒）：

```bash
python scripts\check_object_storage.py
```

## 常见问题

**Q：`docker compose up` 报错连不上 Docker？**
A：Docker Desktop 没启动。打开它，等任务栏图标不再转圈，再重试。

**Q：端口被占用？**
A：在 `.env` 里改对应端口（如 `BACKEND_PORT=8010`），再 `docker compose up -d`。

**Q：想从头来过（清空所有数据）？**
A：`docker compose down -v`，然后重新 `up`。**这会删除数据库与向量库里的全部数据。**

**Q：对象存储的账号密码在哪里改？**
A：**两处都要改，且必须一致**：`.env` 里的 `S3_ACCESS_KEY` / `S3_SECRET_KEY`（应用用），
以及 `deploy/seaweedfs/s3.json`（SeaweedFS 用它校验）。改完执行 `docker compose up -d` 重建容器。

**Q：为什么对象存储不是 MinIO 了？**
A：MinIO 官方已下架全部社区镜像与下载（Docker Hub 404、dl.min.io 410），改用同样提供 S3 协议的
SeaweedFS。对上层使用方式没有区别，详见 [ADR-0004](docs/adr/0004-对象存储选型.md)。

**Q：固定管理员的口令忘了怎么办？**
A：执行 `docker compose exec backend python /app/scripts/reset_admin_password.py`，
会打印一个新口令。这是唯一的自助路径（固定管理员不能被别人重置）。

**Q：第一次部署怎么知道初始口令？**
A：看后端启动日志里"已创建固定管理员"那一行。`.env` 里设了 `BOOTSTRAP_ADMIN_PASSWORD`
就用你设的那个；留空则系统随机生成并只打印一次。

**Q：怎么加一个新的领域（比如法务、医疗）？**
A：在 `domains/` 下新建一个目录，写一个 `manifest.yaml`，重启后端即可。
不需要改任何引擎代码——这条已由自动化测试锁住（验收门 G2）。
加完可以先用 `POST /api/domains/route-preview` 试跑路由效果。
