# 对外接口说明（技术方案 12.4 的落地）

这份文档给**要对接本系统的开发者**看。接口的权威定义是运行中的
OpenAPI 文档：<http://localhost:8000/docs>（可在线试用），
本文只讲怎么用、有哪些坑。

## 一、通用约定

| 项目 | 约定 |
|---|---|
| 前缀 | `/api/v1/`（稳定接口都在这里） |
| 鉴权 | `Authorization: Bearer <令牌>`，令牌来自 `POST /api/auth/login`，有效期 24 小时 |
| 请求体 | JSON（`Content-Type: application/json`） |
| 错误格式 | FastAPI 统一格式：`{"detail": "人能看懂的原因"}`；校验失败为 422 |
| 金额 | **一律传字符串**（`"100000"`），不要传浮点数字——浮点误差会一路进申报表 |
| 时间 | ISO 8601；`as_of` 支持 `2026-06-30T00:00:00Z` 这种写法 |
| 分页 | 列表接口用 `limit` 参数（当前数据量小，未做游标分页） |

## 二、接口清单

### 1. 问答

`POST /api/v1/qa/ask` — 权限 `qa.ask`

```json
{
  "question": "我是小规模纳税人，上个月在市区卖了10万元含税货物，怎么交税",
  "tax_type": null,
  "as_of": null,
  "top_n": 6
}
```

返回里值得注意的四块：

| 字段 | 用途 |
|---|---|
| `answer.sections[]` | 六段式答案。每段带 `renderer`（text / citation_list / formula_steps / ordered_steps / bullet_list / fixed_text），前端按它决定怎么渲染，不要解析文字 |
| `citations[]` | 引用明细：文号、条款号、**效力状态**、生效区间、原文、`article_version_id`（可再查详情） |
| `calculation` | 计算过程（公式 + 代入 + 结果 + 依据） |
| `compliance` | 免责声明、知识截至时间、留痕编号 `trace_id`、是否通过验证 |

`refused=true` 表示**没有给出结论**（检索不到依据、或验证层拦下了）。
这是正常返回，不是错误；调用方应当把 `answer` 照常展示给用户，
而不是显示"系统错误"。

`POST /api/v1/qa/feedback` — 权限 `feedback.submit`

```json
{ "trace_id": "上一步返回的编号", "helpful": false, "reason": "税率用错了" }
```

差评会写进知识缺口清单交专家复核，**不会自动改知识**。

### 2. 引用详情

`GET /api/v1/citations/{article_version_id}` — 权限 `citation.view`

返回原文、效力状态、生效区间、废止/修订依据。
**已废止的条文也能查到**（历史回答里的引用点开不能 404），
但返回里 `repealed=true`，界面必须显眼标出来。

### 3. 税费计算

`POST /api/v1/calc/tax` — 权限 `calc.run`

```json
{
  "taxpayer_type": "小规模纳税人",
  "sales_amount": "100000",
  "amount_includes_tax": true,
  "business_type": "销售货物",
  "location": "市区",
  "include_surcharges": true
}
```

**算不出来时返回 200**，`vat.computable=false` 并在 `notes` 里说明原因
（例如"未确认纳税人身份"）。请不要把这种情况当接口故障重试——
它需要的是补参数，不是重试。

### 4. 筹划分析

`GET /api/v1/planning/profile-schema` — 画像字段与允许取值（前端表单直接用，别抄枚举）

`POST /api/v1/planning/analyze` — 权限 `client.profile.write`

```json
{
  "profile": { "entity_type": "有限公司", "taxpayer_type": "小规模纳税人", "goal": "降低税负" },
  "request_text": "希望在不改变业务的前提下降低综合税负"
}
```

**必须知道的约定**：

1. **筹划总开关关闭时，`plans` 恒为空**（资质主体落实前是关闭状态）。
   持有复核权限的账号仍能看到方案内容，那是内部推演视图。
2. 🔴 高风险方案**永远不会出现在 `plans` 里**，只在复核台可见（`withheld` 字段）。
3. 每个方案都带 `abuse_boundary`（滥用边界）与 `rejected_cases`（被否案例）——
   对外展示时**不要省略**，只讲怎么省税不讲边界，是把风险转嫁给用户。
4. 画像里有拼错的字段会返回 422（不是静默忽略）。

### 5. 专家复核

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/v1/planning/reviews` | `planning.review` | 待办列表（一屏判定所需的全部信息） |
| `GET /api/v1/planning/reviews/workload` | `planning.review` | 待办量、平均处理时长、按时率、超时清单 |
| `GET /api/v1/planning/reviews/feedback` | `planning.review` | 待转评测集的反馈清单 |
| `POST /api/v1/planning/reviews/{id}/decision` | `planning.review` + 高风险需 `planning.review.high_risk` | 放行 / 修改后放行 / 驳回 |

`action` 取值：`approve`、`approve_with_changes`、`reject`。
**驳回必须写原因**（`note`），否则系统学不到东西，用户也拿不到替代方案。

### 6. 管理后台

| 接口 | 权限 | 说明 |
|---|---|---|
| `GET /api/v1/console/overview` | `knowledge.review` / `audit.view` / `system.config` / `index.rebuild` 任一 | 概览 |
| `GET /api/v1/console/gaps` | `knowledge.gap.handle` / `knowledge.review` | 缺口清单 |
| `GET /api/v1/console/evaluations` | `knowledge.review` / `system.config` | 评测报告与门禁结论 |
| `GET /api/v1/console/policy-changes` | `knowledge.review` / `planning.review` / `audit.view` | 政策变化摘要与事件 |
| `GET /api/v1/console/audit-logs` | `audit.view` | 审计留痕（只读） |

`overview.index_points` 为 `null` 表示**读不到**，不是"索引是空的"。
两种情况的处置完全不同，界面上必须区分。

## 三、还没做的（对接前请确认）

| 项 | 现状 | 影响 |
|---|---|---|
| 限流 | 未做 | 对外提供前必须按租户配额加限流 |
| 幂等键 | 未做 | 写操作重试可能产生重复记录 |
| 异步筹划 | 未做（同步返回，约 1～3 秒） | 接入 LLM 后必须改异步 |
| 任务查询 `GET /v1/planning/tasks/{id}` | 未提供 | 随异步版本一起加 |
| Webhook 推送 | 未做 | 政策变化/复核结果/答案反馈目前只能轮询 |
| 流式输出 | 未做 | 长答案首屏等待约 2～5 秒 |

## 四、本地试一遍

```powershell
# 1. 拿令牌
$body = @{ username = "root_admin"; password = "<你的口令>" } | ConvertTo-Json
$token = (Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/auth/login `
  -ContentType "application/json" -Body $body).access_token

# 2. 提问
$headers = @{ Authorization = "Bearer $token" }
$ask = @{ question = "小微企业有什么税收优惠" } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://localhost:8000/api/v1/qa/ask `
  -Headers $headers -ContentType "application/json" -Body $ask
```

浏览器里直接看接口文档并试用：<http://localhost:8000/docs>
