# ADR-0011 附件正文解析（正文不在网页上的文件怎么收）

- 状态：已采纳（accepted）
- 日期：2026-10-01
- 决策者：项目负责人

## 背景

官方政策法规库里有一批文件，**正文不在网页上，而在附件里**。
网页正文只剩一句"现将《XX办法》印发给你们，请遵照执行"，外加一个附件链接。
典型的是各类"管理办法""总体方案""文书式样"。

采集器按"有没有条款结构"判断，会跳过这类文件，
避免把"现予公布《XX目录》"这种噪声灌进知识库。但代价是这些文件也没进来，
其中包含《残疾人就业保障金征收使用管理办法》（财税〔2015〕72号）这种核心文件。

2026-10-01 做 F 专题时解决。

## 决策

### 一、正文太短或明显是"发布通知"时，先尝试解析附件

判定顺序：

1. 网页正文足够长且不是发布通知 → 直接用网页正文
2. 否则找出页面上的附件链接（`href` 以 .doc/.docx/.pdf/.wps 结尾）
3. 下载后按**文件实际格式**解析（见下）；解出的正文 ≥ 阈值就用它
4. 都失败才跳过，并把原因写进跳过清单

### 二、按文件头判断格式，不能信扩展名

这是本次踩到的坑：**官网把 Word 97-2003 二进制文档命名为 .docx**。
按扩展名走 `word/document.xml`，会直接报"压缩包里没有这个文件"。

改用文件头：

| 文件头 | 实际格式 | 处理 |
|---|---|---|
| `%PDF` | PDF | 用 pypdf（未安装则跳过并记录） |
| `D0 CF 11 E0 A1 B1 1A E1` | OLE2 容器（.doc / .xls / .wps） | 按 UTF-16LE 扫正文 |
| `PK\x03\x04` | zip 包 | 有 `word/document.xml` 是 docx；有 `xl/` 是 xlsx（暂不支持） |

### 三、OLE2 老式 Word 用"扫 UTF-16LE 片段"抽正文

Python 生态里没有轻量的 .doc 解析器（python-docx 只支持 docx，textract 要拖重依赖），
而政府网站上的老文件大量是这种格式。做法是按 UTF-16LE 解整份文件、
扫出连续的可读片段。粗暴但有效：实测《残疾人就业保障金征收使用管理办法》
能完整抽出 4794 字、27 个条文标记、5 个章节标记。

**两个必须有的过滤器**（都是实测踩出来的）：

1. **错位 ASCII 过滤**：文档里嵌的 XML（如 `settings.xml`）按 UTF-16LE 解出来
   会变成"湯整瑮呟灹獥"这种伪中文。判据是把字符还原成两字节并交换顺序，
   若**全部**是可打印 ASCII 就判定为错位字符串。
   ⚠ 阈值必须是"全部"，不能放宽到 80%——"第一条"错位后是 `,{\x00Nag`，
   含不可打印字节，用 80% 阈值会把条文标记全部误杀（实测整份办法从 43 条掉到 4 条）。
2. **粘连标记过滤**：`第一章湯` 这种"结构标记后面直接粘乱码"的行要丢掉；
   正常写法是"第一章 总则"（有空格）。

### 四、xlsx 与 PDF 的处理

- **xlsx**：暂不支持。这类附件多是税率表、目录表，结构化程度低，
  硬抽出来是一堆数字，对问答没有价值。
- **pdf**：需要第三方库 pypdf（**本项目唯一的脚本级新增依赖**，
  纯 Python，约 400KB，不拖其它包）。已装，记录在 `scripts/requirements.txt`。
  没装时优雅跳过并记录，不让整批采集崩掉。
  已验证可解析：《关于完善残疾人就业保障金制度更好促进残疾人就业的总体方案》
  （发改价格规〔2019〕2015号，3489 字）、
  《社会保险费及其他基金规费文书式样》公告（19363 字）。

> 提醒：扫描件 PDF（没有文字层，只有图片）无法用 pypdf 抽正文，
> 这类文件只能靠 OCR，不在当前范围。

## 后果

- docx 与老式 doc 用标准库解析（zipfile + 正则），**零依赖**；
  只有 PDF 需要 pypdf。
- 已捞回：残保金办法（43 条）、残疾人就业保障金缴费申报表公告、
  调整消费税纳税申报表公告、部分行业企业工伤保险费缴纳办法、社会保险费征缴监督检查办法等。
- 检索效果："残保金怎么算"现在第一位是财税〔2015〕72号 第四条（修前这个文件不在库里）。
- 仍缺：PDF 附件型文件；xlsx 附件型文件。
