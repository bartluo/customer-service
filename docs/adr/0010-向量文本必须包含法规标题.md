# ADR-0010 向量文本必须包含法规标题

- 状态：已采纳（accepted）
- 日期：2026-10-01
- 决策者：项目负责人

## 背景

2026-10-01 补完"增值税发票专题"后验收，发现一类问题整批失效：

> 问"全面数字化电子发票怎么开"，正确答案是
> 《国家税务总局关于推广应用全面数字化电子发票的公告》，
> 而语义检索前 6 名里根本没有它。

原因在索引侧：写入向量库时**只取条文正文，不取法规标题**。
那份公告的条文正文里没有"全面数字化"这四个字，
用户按文件名描述来问，向量层面无论如何都匹配不上。

早期这么设计是有理由的，代码注释写着：
> "标题每条都重复，会让所有向量彼此相似，反而拉低了区分度。"

这个顾虑本身成立，但代价算错了：财税用户问问题，很大一部分是
"**那份关于 XX 的文件怎么规定的**"——按文件问，不是按条文原话问。
标题不进向量，这一整类问题都会失效。

## 决策

**向量文本 = 法规标题 + 换行 + 条文正文**，稠密与稀疏向量共用这份文本。

| 取舍 | 说明 |
|---|---|
| 得到什么 | "按文件问"整类问题可召回；标题里的专有名词（数字化电子发票、六税两费）也能被稀疏路由精确命中 |
| 付出什么 | 每条向量多十几到几十个字的共同前缀，理论上略降区分度 |
| 为什么可接受 | 标题十几个字，条文正文动辄几十上百字，占比很低；且财税同税种条文本来就高度相似，区分度主要来自正文而非标题 |

## 备选方案

**A. 只让稀疏路由带标题，稠密仍是纯正文。**
否决：索引器一次调用 embedding 服务同时产出稠密与稀疏，两者来自同一段文本。
要分开就得改 embedding 服务接口，为一个可以避免的复杂度不值得。

**B. 把标题写进 payload 用过滤解决。**
否决：用户问的是自然语言，不是精确标题；过滤要求先猜中标题，等于把问题推回给用户。

**C. 维持原样，靠术语表补同义词。**
否决：文件主题的表达方式几乎无限（"全电发票""数字化电子发票""全面数字化电子发票"），
枚举不可能覆盖。

## 后果

- 修后实测："全面数字化电子发票怎么开" → 国家税务总局公告2024年第11号（正确）。
- 发票专题 6 个典型问题全部命中发票类文件。
- **必须重建向量索引才生效**——向量文本变了，旧向量与新向量不可比。
- 这条改动同时提升了所有专题的"按文件问"能力，不限于发票。
