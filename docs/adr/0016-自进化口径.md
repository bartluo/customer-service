# ADR-0016 自进化：按来源判重、只发现不自动入库、解读不作依据

- 状态：已采纳（accepted）
- 日期：2026-10-01
- 决策者：项目负责人

## 背景

本决策落地技术方案第 8 章。一句话说清这一层的理由：

> **财税知识的过期不是因为"没人用"，而是因为政策改了。**

所以必须有主动的变更监控，而不是等用户发现答案不对。

## 决策

### 一、变更监控按**来源 URL** 判重，不按标题

官方页面重新排版时标题会变（空格、书名号、"（试行）"后缀），
按标题判重会把同一份文件反复当成"新发现"，监控很快就全是噪声。
来源 URL 是稳定标识。

另外，`http://www.chinatax.gov.cn` 与 `https://fgk.chinatax.gov.cn` 是同一份文件的两个域名，
判重前必须归一化——这一条是实测踩出来的。

### 二、监控只**发现**，不自动入库

发现是机器的事，入库要过复核。自动把抓到的文件直接发布，
等于绕过了验证层与人工复核——**那两层的存在意义就没了**。

### 三、影响分析用规则抽"点名废止/修订"，不用模型

中文法规里"废止/修订"的写法是固定的：

> "《中华人民共和国增值税暂行条例》同时废止"
> "决定对《XX办法》作如下修改"

规则抽取可靠、可复现、可回归测试。模型适合处理的是"换个说法"的表述，
而那属于补充而非主力。

判断"解读性文章"也用规则：标题带"解读/问答/答记者问"且正文没有条款结构——
**把解读当法条是财税问答的典型事故**，这类必须归档、明确不作为引用依据。

### 四、缺口主题的税种识别，复用检索层同一套逻辑

先认税种全名，再用术语扩展兜口语说法（"小规模""进项"）。
不这么做会出现"检索按增值税过滤、缺口却归到未标注"的口径错位，
缺口统计就没法用来指导补数据。

### 五、health_score 以**效力信号**为主

技术方案 8.1 指出财税域的特殊性：衰退的主要触发器是"法规效力变化"，
不是"没人用"。所以扣分权重按效力 > 来源 > 完整性 > 时长排列。

系统目前还没有"被引用次数"的埋点，所以只用现有信号——
这一点如实反映在扣分项里，**不装作有不存在的数据**。

### 六、没有推送通道就如实说明

`delivery` 字段写的是"未配置推送通道（摘要已生成）"。
硬写一个假的"已推送"比不推送更糟：用户会以为订阅生效了，
于是不再自己去核政策。

### 七、验收脚本必须清理自己塞进去的数据

G8 的模拟会在库里造一份"废止决定"。第一次跑完忘了清理，
这份**假法规就留在了知识库里，会被检索、被引用**。
已加清理逻辑，并写进这条 ADR：
**验收脚本不能污染生产数据。**

## 后果

- 验收门 G8 达成：`scripts/verify_evolution.py` → **16/16 通过**，
  含"模拟一次政策修订，从发现到知识更新完成 ≤ 24 小时"（实测约 31 分钟，
  其中绝大部分是索引重建）。
- 四类流水线可用：资料摄入（已具备）、缺口发现、衰退淘汰、变更监控。
- 新增测试 18 项，后端测试总数 442 项全绿。

## 已知限制

- 知识抽取流水线的"自动"部分：目前是人工投放 + 采集脚本触发，
  尚未做定时任务编排（Celery beat）。
- 推送通道：摘要能生成，但没有邮件/短信/站内信通道，未接入订阅关系表。
- 「修改后 60 秒内可检索」：放行会触发队列重建索引，
  但**全量重建在 CPU 上要十几分钟**，达不到 60 秒。
  需要改成增量索引（只重建受影响的条文）才能满足这条指标。
