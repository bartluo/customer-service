# ADR-0006 效力状态枚举统一（财税域）

- 状态：已采纳（accepted）
- 日期：2026-09-29
- 决策者：项目负责人

## 背景

实现中发现两处定义不一致：

- 技术方案 v3.3 第 4.1 节给出 6 种效力状态：
  `not_yet_effective / effective / partially_repealed / repealed / superseded / draft`
- `domains/finance_tax/ontology.yaml` 给出的是另一套 6 种：
  `effective / amended / repealed / expired / superseded / pending`

效力状态是"废止条文绝不能出现在答案里"这条硬规则（ontology `no_cite_repealed`）的输入。
枚举一旦分叉，检索硬过滤、时效验证器、审核台三处会各写各的，属于会静默出错的分歧，
因此必须在写第一行业务代码之前定死。

## 决策

**以技术方案 v3.3 的 6 种为唯一权威枚举**，代码与 ontology.yaml 全部对齐到它。

理由：`partially_repealed`（部分废止）是财税场景的刚需。一部法规整体仍然有效，
但其中某一条被单独废止或修改，是极其常见的现象（如财税〔2019〕39 号这类修改公告）。
旧枚举里的 `amended` 表达不了"这一条被改过、那一条没动"，而 `partially_repealed` 可以。
另外 `draft` 把"征求意见稿等未正式发布文本"明确隔离出来，避免采集到草案却被当成依据。

## 旧枚举的迁移映射

| 旧 code（ontology v1） | 新 code | 迁移说明 |
|---|---|---|
| `effective` | `effective` | 一致，不变 |
| `pending` | `not_yet_effective` | 仅改名，语义一致 |
| `amended` | `superseded` | 语义收紧：旧版本被修订后即由新版本取代，旧版本不再可直接引用，必须改引新版 |
| `expired` | `repealed` | 并入"已废止"。单纯超过有效期的情况由时间区间 `[valid_from, valid_to)` 表达，不另设状态 |
| `repealed` | `repealed` | 一致，不变 |
| `superseded` | `superseded` | 一致，不变 |
| （无） | `partially_repealed` | 新增 |
| （无） | `draft` | 新增 |

## 后果

- `effective` / `partially_repealed` 可引用；`not_yet_effective` 为条件可引用（只提示不引用）；
  `repealed` / `superseded` / `draft` 一律禁止引用。
- 旧枚举不再保留别名，避免"两套名字长期共存"造成的隐性不一致。
- 代码侧枚举落在 `backend/app/knowledge/ontology.py`，并由测试断言与
 `domains/finance_tax/ontology.yaml` 完全一致，防止再次漂移。
