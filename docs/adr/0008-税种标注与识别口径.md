# ADR-0008 税种标注与识别口径

- 状态：已采纳（accepted）
- 日期：2026-10-01
- 决策者：项目负责人

## 背景

2026-09-30 采集 82 份法规入库后做覆盖度体检，发现一条会静默出错的链路：

**采集侧标错。** 这 82 份文件的税种标签**全是"增值税"**，
连《中华人民共和国个人所得税法》的标签也是"增值税"。
直接原因是采集脚本给这批文件统一写了栏目分类码 `cn_tax_admin`，
而导入器的映射把 `cn_tax_admin` 一律翻译成"增值税"。

**检索侧认不出。** 检索会用问题里的税种给召回加过滤（`filters.py`），
但税种是从术语表的口语别名里推的，表里只登记了"小规模""进项""个税""印花"
这几十个词。用户直接写税种全名（非常常见）时一个都认不出来，等于没加过滤。

**别名互相吃掉。** 术语表里有别名"所得税"（→企业所得税），
它会匹配进"个人所得税"，于是用户问个税、系统去搜企业所得税的条文。

三条叠在一起的实际表现：问"个人所得税怎么算"召回企业所得税法，
问"房产税如何计算"召回契税法，问"土地增值税怎么算"召回增值税法。

## 决策

### 一、税种名单唯一化

全系统只有一份税种名单，放在 `backend/app/domain/tax_types.py`，
采集侧与检索侧共用。两处各写一份，迟早出现"采集标了、检索认不出"的错位。

### 二、标注优先级（有才用，没有就往下退，绝不硬猜）

| 优先级 | 来源 | 说明 |
|---|---|---|
| 1 | sidecar 里写明的 `tax_types` | 人工校对过的值 |
| 2 | 官方"税费类型"字段 `tax_policy` | 网站自己标的，最权威；形如 `税收政策-个人所得税` |
| 3 | 清洗脚本留下的 `collection` 标记 | 旧数据用 |
| 4 | 标题里的税种名 | |
| 5 | 正文里出现 ≥2 次的税种 | 最多取 2 个 |

第 5 条要求"出现 2 次以上且最多 2 个"，是因为长公告正文会顺带提到很多税种，
直接扫正文会打出"企业所得税/增值税/消费税/会计"这种四标签，
过滤时反而把不相关的条文放进来。

### 三、识别按"长名优先，命中即挖掉"

`detect_tax_types()` 匹配到税种后立刻把它从待匹配文本里挖空，
否则"土地增值税"会被"增值税"先吃掉，用户问土地增值税、过滤器里却是增值税。

### 四、口语别名必须写完整词

术语表的别名不能是可嵌入更常见词的碎词。典型案例：
别名"附加"会把"专项附加扣除"里的"附加"算成城建税附加。
改为"附加税""附加税费""教育费附加"。

**验收口径**：新增任何术语别名，都要能回答"它会不会出现在一个跟本税种无关的常见词里"。

## 后果

- 修复后 21 个税种都有对应法规，标签分布合理（增值税 27、企业所得税 14、发票 9……）。
- 10 个常见问题实测全部落到正确税种（含"个人所得税怎么算""房产税如何计算"
  "土地增值税怎么算""城镇土地使用税怎么交"）。
- 税种同时存在于数据库和向量库 payload，改标签要**两处同步**：
  `scripts/repair_regulations.py` 已支持（改库 + `set_payload` 同步索引，不重算向量）。
- 仍存在的数据缺口：标签为空（10 份）的法规在"按税种过滤"的检索里不会被召回，
  它们多是税收协定、执法文书式样这类确实不属于某一税种的文件，属预期行为。
