# ADR-0004：对象存储由 MinIO 改用 SeaweedFS

**状态**: accepted
**日期**: 2026-09-29
**决策者**: 用户（由技术方提出并说明影响）
**取代**: 技术方案 v3 第 6.1 节中"对象存储用 MinIO"的选型（该选型当时未单独成 ADR）

## 背景

原技术方案（v3）里，本地与私有化部署的对象存储选型是 MinIO，用来存放法规原件 PDF、
教材与题库 Excel、以及各类快照，并通过 S3 协议供应用读写。

2026-09-29 实际搭建环境时发现：**MinIO 已停止对外分发社区版镜像与二进制**。实测证据：

| 检查 | 结果 |
|---|---|
| Docker Hub 仓库 `minio/minio` | HTTP 404（仓库已不存在） |
| Docker Hub 仓库 `minio/mc` | HTTP 404 |
| `docker pull minio/minio:latest` | `pull access denied ... repository does not exist` |
| `quay.io/minio/minio:latest` | HTTP 401 UNAUTHORIZED |
| 官方下载站 `dl.min.io`（服务端与客户端） | HTTP 410 Gone |
| Bitnami 免费镜像 `bitnami/minio` | 已无可用标签（2025-08 迁移到 `bitnamilegacy` 存档库） |

也就是说，这不是本机网络问题，而是上游分发策略变化，**任何新装的机器都拉不到 MinIO**。

## 决策

对象存储改用 **SeaweedFS**（`chrislusf/seaweedfs`，Apache-2.0），仍以 **S3 协议**对外提供服务。

实现要点：

1. 镜像按 **摘要（digest）固定**，不用漂移的 `latest`，避免某天镜像被替换导致环境悄悄变化。
2. 单进程拉起 master + volume + filer + S3 网关（`weed server -s3`），开发与中小规模私有化一套配置。
3. 开启 IAM（`-s3.config`），**匿名访问一律拒绝**，并区分三个账号：

   | 账号 | 权限 | 用途 |
   |---|---|---|
   | `cs_s3` | 仅 `customer-service` 桶的读写与列举 | 应用使用 |
   | `cs_s3_backup` | 仅该桶的只读 | 备份与巡检 |
   | `cs_s3_admin` | 管理员 | 人工排障，**不写进应用配置** |

4. 建桶由一次性任务 `s3_init` 完成，跑完即退出（`Exited (0)` 属正常）。

## 备选方案

**Alternative 1：继续用 MinIO 存档镜像 `bitnamilegacy/minio:2025.7.23`**
- 优点：与现有文档一致，零改动
- 缺点：镜像已冻结、不再有安全更新，存档库随时可能被删除
- 否决原因：对象存储是所有原件的落地点，把安全底子压在已停更的镜像上不可接受

**Alternative 2：Garage（`dxflrs/garage`）**
- 优点：轻量、S3 兼容、Rust 实现
- 缺点：配置需先手工规划集群 layout，运维步骤比 SeaweedFS 多
- 否决原因：现阶段要的是"一条命令起环境"，复杂度换不来收益；可作为备选保留

**Alternative 3：Ceph RGW**
- 优点：企业级成熟，功能最全
- 缺点：至少 3 节点、运维重、资源占用高
- 否决原因：与"中小规模可私有化"的定位不匹配

**Alternative 4：先不装对象存储，用本地磁盘**
- 优点：最少依赖
- 缺点：云端要换 OSS 时仍要重写存储层
- 否决原因：既然统一按 S3 协议封装，越早对齐接口，后面迁移越省事

## 后果

**正面**

- 继续按 S3 协议开发，云端换成阿里云 OSS / 腾讯云 COS 只改地址与密钥，应用代码不用改。
- 自带文件浏览器（`:8888`），可替代原 MinIO 控制台做人工抽查。
- 单一进程即可跑通，私有化部署的机器要求低。

**负面 / 需要留意**

- SeaweedFS 的 S3 权限模型比 MinIO 粗（按桶授权，没有细到前缀级策略）。
- 文档与脚本里原 `MINIO_*` 变量已更名为 `S3_*`，旧笔记需要同步。
- 应用侧密钥必须与 `deploy/seaweedfs/s3.json` 保持一致，改一处要改两处（后续做配置校验脚本自动检查）。

**风险与缓解**

| 风险 | 缓解 |
|---|---|
| 镜像 `latest` 标签内容变化 | 已用 digest 固定 |
| 密钥两处不一致导致读写失败 | 应用启动即做一次读写自检，失败直接报错指出文件位置 |
| 数据量增大后单进程扛不住 | `weed server` 可按角色拆分部署，S3 协议不变，迁移无需改应用 |
