# ADR-0019 对外接口层口径：版本化、如实报错、筹划开关只拦"对外"

- 状态：已采纳（accepted）
- 日期：2026-10-02
- 决策者：项目负责人

## 背景

对外接口层把前面各层的能力（检索、推理、计算、验证、筹划、自进化、评测）
接到界面上，并按技术方案 12.4 预留对外接口。这一层最容易出的问题不是"写不出来"，
而是三种"看起来没问题、用起来会误导"的做法。下面每条都是实际遇到并做了取舍的。

## 决策

### 一、对外接口统一挂在 `/api/v1/`，与旧的 `/api/*` 并存

新接口一律 `/api/v1/...`（qa / calc / citations / planning / console），
原有的 `/api/auth`、`/api/admin`、`/api/knowledge` 保持不变。

为什么不把旧的也一起搬到 v1：**版本号是给外部调用方的承诺**。
已经接进去的调用方（以及我们自己的前端）不该因为一次内部重构就全部改地址
（Hyrum 定律：只要能观察到，就有人依赖）。新增能力用 v1 表达"这部分契约稳定"，
旧路径继续按原样提供服务；将来要收敛时走弃用流程，而不是一次性切换。

### 二、算不出来返回 200，不返回 4xx

`POST /api/v1/calc/tax` 在"没给纳税人身份，无法确定计税方法"时返回 **200**，
响应里 `computable=false` 并说明原因。

理由：这不是接口调用错误，而是一个需要用户补信息的正常结果。
报 4xx 会让调用方以为接口坏了，把"待确认"当成失败丢掉；
而财税场景里"待确认"恰恰是要交给用户看的结论。
真正该报 4xx 的只有一类：**请求本身不合法**（金额不是数字、画像取值不在允许范围）。

同理，`/v1/planning/analyze` 在画像字段拼错时返回 422 并说明哪个字段，
而不是静默忽略——静默忽略等于"用户填的收入根本没进模型"，方案会基于缺数据生成。

### 三、筹划总开关管的是"对外产出"，不是"内部不能推演"

`planning_enabled`（ADR-0015，资质主体落实前保持 false）在接口层的落地是：

| 场景 | 谁能看到方案 |
|---|---|
| 开关开启 | 所有人（按风险分级：🔴 仍然只进复核台） |
| 开关关闭 | **只有持有复核权限的审核专家**；客户角色的 `plans` 恒为空，并附原因说明 |

为什么不做成"开关关闭就整页 403"：那样复核台就没有任何数据，
专家在资质落实前无从准备，等开关一开就是从零开始试。
而筹划引擎的内部推演本身不产生对外风险——**风险来自"把方案发给客户"这个动作**，
所以开关卡在这个动作上。

验收脚本会真的建一个**客户角色**账号去打这个接口，确认拿到的是空方案 + 原因说明。
用固定管理员测不出来——固定管理员对所有权限都放行。

### 四、域包文件路径统一由 `config.domain_file()` 解析

本机开发时 `backend/app/xxx.py` 往上数三层是仓库根；容器里同样的代码路径
往上数三层是 `/`，而域包实际在 `/app/domains`。
这类"本机全对、容器全错"的问题要等到第一次在容器里跑推理链路才暴露
（第一次在容器里调问答接口就炸在模板文件找不到）。

现在统一走 `app.config.domain_file()`：先按配置的 `domains_root` 找，
找不到再退回"仓库根/domains"。五个模块（模板、推理配置、税率规则、红线规则、手法库）共用。

## 与规格的一处有意偏离

规格要求筹划分析**异步执行**（返回任务 ID + 回调）。
本版是**同步返回**的，原因：本地规则引擎跑一次筹划分析约 1～3 秒，
引入任务队列只会让"提交 → 轮询 → 取结果"多三个来回并多一处会失败的地方；
规格要异步的真实原因是"耗时操作不能阻塞调用方"，这个原因在 1～3 秒的量级上不成立。

等接入 LLM 生成方案（单次数十秒）时再改异步，届时任务表与回调一起加。
**`GET /api/v1/planning/tasks/{id}` 这条路径因此暂未提供**，需要时按异步版本补。

## 后果

- 前端 9 个页面全部由这一层供数；验收脚本 `scripts/verify_api.py` 覆盖 25 项。
- 问答接口额外返回 `citations`（含条文版本 ID 与效力状态）与 `compliance`
  （免责声明 / 知识截至时间 / 留痕编号），界面才能做到"每条依据都能点开核对"。
- 每次问答都写一条审计留痕（`qa.ask` + trace_id），事后可追查"当时问了什么、引用了什么"。
- 修掉了域包路径在容器内解析错误的缺陷（一直存在，只是没在容器里跑过）。

## 已知限制

- **前端令牌存在 localStorage**：这是首版的取舍（实现简单、无跨域 Cookie 问题），
  代价是 XSS 可以直接读走令牌。私有化部署场景风险可控，
  但要对外提供服务前应改为 httpOnly Cookie 或后端签名代理。
- **流式输出未做**（技术方案 7.4 建议"判定先出、依据后出"）。
  当前是整段一次性返回；答案长时首屏等待约 2～5 秒。
- **限流与幂等键未做**（12.4 的接口设计要点）。当前是单租户自用规模，
  对外提供前必须补上按租户配额的限流与写操作幂等。
- **Webhook 三个出向接口未做**（政策变化推送、复核结果通知、答案反馈）。
  推送通道本身也尚未配置（推送通道的口径是"不假装已发送"）。
