# ADR-0017 评测与门禁口径：红线不参与打分

- 状态：已采纳（accepted）
- 日期：2026-10-02
- 决策者：项目负责人

## 背景

评测与门禁要回答一个问题：**这套系统现在到底能不能上线，凭什么说能。**

做法是"跑评测集 → 出指标 → 按指标判放行或阻断"。这条路最容易走歪的地方有四个，
下面每一条都是实际验证过的口径。

## 决策

### 一、一票否决项单独判定，不参与打分

财税域的硬红线只有一条先落地：**引用了已废止条款**。

它必须走独立的判定分支：只要出现 1 条，整批发布阻断。

为什么不能做成"加权打分、总分够就放行"：
红线会被平均数稀释。100 条题里泄漏 1 条，通过率还是 0.99，
总分漂亮得很——但用户拿到的就是废止条款。**红线的性质是"有就是错"，
不是"少就是好"。** 加权打分把这两种性质混成了同一种。

指标里同时保留"通过率"和"Recall@5"这类常规阈值，
但它们走另一条分支（`THRESHOLDS`），与红线分开记：
不达标一样阻断，但**不记进一票否决项**。两类问题的处置不一样，
混在一起，"到底能不能发"就变成一句含糊的话。

### 二、废止陷阱的判据是**身份比对**，不是标题子串匹配

废止陷阱题的工作方式是：给出"禁止出现的引用"，看系统有没有引用它。
这里只能比对**文件身份**（文号，法律/行政法规退化为法规名称）。

为什么不能用标题子串匹配：库里有一份**仍然有效**的
《国务院关于废止〈营业税暂行条例〉和修改〈增值税暂行条例〉的决定》，
它的标题里就含有"增值税暂行条例"。子串匹配会把这份有效文件报成
"引用了废止条款"。

误报的代价不只是错一次：**门禁老是报假警，人就不再看它了。**
一个没人看的门禁等于没有门禁。

### 三、失败的题必须记 0 分，不能"没有指标就跳过"

失败的标准题必须带 `metrics` 并计 0 分；只统计"有指标的题"会让失败被掩盖。
结果：30 条题挂了 29 条，算出来 Recall@5 = 1.0。

这不是小数点问题，是**指标在骗人**。现在的规则是：
失败题一律记 `recall=0`，并且单测锁住这条。

### 四、标准题必须带话题线索，判定口径才公平

同一类问题下往往有多条条文都算对。问"申报怎么缴"，
只认某一条具体条款，会把正确答案判成错的。

所以标准题除"期望引用"外，还必须带**内容线索**（`expected_points`）：
Top5 里只要有一条在讲这个话题就算命中；能精确命中期望条款时，
额外记录它的位次，作为更严的参考值。

### 五、"信息不足题"必须问"我这种情况"

信息不足题必须问"我这种情况"，不能写"增值税怎么交"这类通用问法。
那属于政策查询，系统直接回答是**对的**——拿它当"应该追问"的题，
等于要求系统对通用问题也反问，口径从一开始就是错的。

现在的判据：问题必须带第一人称（"我这个业务……""我这种情况……"），
缺关键要素才期望追问。第一人称判据写在
`app/reasoning/pipeline.py::_needs_clarification`。

### 六、评测题一律以 draft 入库

系统生成的候选评测题**一律 draft**，标准答案必须由内部专家确认后才转 approved。

理由很直接：让系统自己出题、又自己判卷，等于把"对不对"交给同一个可能出错的环节。
评测集的分数是上线判据，判据不能自证。

## 后果

- 验收 `python scripts/verify_evaluation.py` → **16/16 通过**，
  含验收门 G9-D：故意把一条已废止法规标成"现行有效"并重灌索引，
  评测能发现、门禁阻断、并给出失败用例明细。
- 评测集 271 条（标准 166 / 废止陷阱 45 / 信息不足 60），全部 draft 待专家确认。
- 实测指标：Recall@5 = 0.933、MRR@5 = 0.799、废止陷阱泄漏 0、信息不足硬答 0。
- 新增后端测试 13 项（一票否决、灰度阶梯、回滚留痕、身份比对、
  失败记 0 分、单份索引重建往返）。

## 已知限制

- **筹划评测集 200 条（含 25% 红线陷阱）未做**：筹划手法素材只有 8 条示例，
  素材不足时造出来的题没有评审价值。等专家素材到位再做。
- **指标看板未做**：评测结果已落库（`eval_runs`），后端接口齐了，
  前端看板待做。
- **评测题评审需要人**：271 条全部 draft，需要内部专家确认标准答案。
- **半自动维度（事实正确性、LLM 裁判）未接入**：本版只统计"有标准答案的题"的命中情况，
  没有标准答案的题明确标注为"未判定"——**不把"没判"算成"通过"**。
- 灰度与影子闸目前只做**判定与留痕**，真正切换流量由 CI/CD 负责。
