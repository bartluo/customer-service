# ADR-0020 答案优先：先给结论，文号只能当备注

- 状态：已采纳（accepted）
- 日期：2026-10-02
- 决策者：项目负责人

## 背景

试用时发现「情形判定」段长这样：

```
根据您的描述推测您的身份为：小型微利企业（尚未确认）
可以适用：国家税务总局公告2023年第6号 三、；财政部 税务总局公告2023年第12号 四、；
          国家税务总局公告2023年第6号 一、
不适用：财政部 税务总局公告2020年第24号 全文（该条款限定适用主体为"个体工商户"…）
需确认：该条款未包含可自动判定的适用条件，需人工核对…
```

原话是：**"现在直接给了（适）用文件，这不是我需要的，应该是你给我答案，
完了备注说明依据哪些文件。"**

一句话说清问题：这段是**文件清单**，不是**答案**。
用户看完既不知道政策讲了什么，也不知道自己该怎么办——
而那正是他花钱买这个系统的原因。

## 决策

「情形判定」段按四步走，**条文要点在前、出处作为括注在后**：

1. 先复述"您的情况"（推测出来的身份必须标"尚未确认"）
2. 能算出数就把结论顶到最前面：`结论：本期应纳增值税 2,912.62 元（计算过程见下一段）`
3. 每条适用政策给出**条文要点**（原文首句，最多 90 字）
   → `小型微利企业…按20%的税率缴纳企业所得税。（出处：财政部 税务总局公告2023年第12号 四、）`
4. 需要确认的、已排除的，各一句话讲清原因

「政策依据」段保持为可点开的引用卡片——**它的定位就是"备注：依据哪些文件"**。

## 为什么不整段照搬条文

财税条文动辄上百字，整段贴进答案会把结论淹没。
要点取首句、超出 90 字截断，要看全文点开引用卡片。
这条边界要守住：**答案给结论，原文给核对**。两者的用途不同。

## 补充说明：优先给答案而不是条文清单

「风险提示」段出现过三个**空的项目符号**（原因是 `reason` 为空串）。
空条目比没有这一栏更糟——用户会以为"这里有内容但没显示出来"。
现在空串与空白条目一律过滤。

## 后果

- `scripts/verify_api.py` 增加检查：答案必须带条文要点与"出处"，且不能是旧的文件清单写法。
- 新增两个回归测试锁住口径（见 `backend/tests/test_answer_g5.py`）：
  `test_judgement_gives_the_answer_not_a_file_list`、
  `test_risks_never_contain_blank_bullets`。
- 后端测试从 455 增至 **457** 项。

## 已知限制

- **要点仍是"首句"，不是真正的摘要**。有些条文首句是套话
  （"各省、自治区、直辖市…：" 这种抬头），要等接入 LLM 做摘要才能改善。
  在接入之前，"首句 + 可点开原文"是诚实的下限——不假装系统读懂了。
- **适用性判定偏宽**：只要条文里出现用户的主体身份词，就可能被判"可以适用"，
  哪怕那条讲的是别的事（例如对一般纳税人讲"超过标准要转一般纳税人"）。
  这是准确度问题，不是格式问题，需要单独做一轮相关性收紧。

## 补充约定：先回答，再问缺失信息

1. **用户已经说过的信息不再复述**，直接进入结论。
2. **段落标题用用户看得懂的说法**，不用内部术语。
3. **涉及主体的政策问题，主体不明就先问主体**，不替用户假设身份。
4. 口径调整后，评测集的标准答案同步更新，保证门禁判定与之一致。

## 补充约定：给"能省多少"，不是把条文念一遍

1. **把写明数额的条文捞出来**（免征额、扣除标准、税率），再过一遍适用性判定，
   命中就给出可核对的金额。
2. **金额一律由计算引擎算**，答案里给出"少缴多少"与算式。
3. 无法给出金额时（条款没写数额、条件不全）**明确说明原因**，不硬编数字。
