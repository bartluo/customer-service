# ADR-0012 时效性治理：官方时效性必须落进效力状态

- 状态：已采纳（accepted）
- 日期：2026-10-01
- 决策者：项目负责人

## 背景

2026-10-01 做 D 专题时核查发现：库里 **297 份法规、7110 条条文，效力状态全是"现行有效"**。

而官方政策法规库对每份文件都标了时效性，采集时留下的元数据显示：

| 官方时效性 | 份数 |
|---|---|
| 全文有效 | 106 |
| **全文废止** | **46** |
| **已修改** | **29** |
| 全文失效 | 1 |
| 尚未生效 | 1 |
| （无记录） | 其余 |

也就是说：**45 份已废止、29 份已被替代的法规，一直在被检索引出来当依据。**

典型后果：问增值税，答案可能引用《中华人民共和国增值税暂行条例》
（2026 年增值税法施行后已废止）。这不是数据多少的问题，是答案对错的问题。

根因：导入器把 `effect_status` **写死**成 `effective`，
采集侧虽然拿到了官方时效性，但只存进了 sidecar，从来没往库里落。

## 决策

### 一、官方时效性 → 本项目效力状态的映射（唯一一处）

放在 `backend/app/domain/effect_status.py`，采集侧与数据核查脚本共用：

| 官方时效性 | 本项目 effect_status | 能否直接引用 |
|---|---|---|
| 全文有效 | `effective` | ✅ |
| 部分失效 | `partially_repealed` | ✅（引用前需核具体条款） |
| 已修改 | `superseded` | ❌ 须改引新版 |
| 全文废止 | `repealed` | ❌ |
| 全文失效 | `repealed` | ❌ |
| 尚未生效 | `not_yet_effective` | ❌ 只能提示"自X日起施行" |

映射依据 ADR-0006 的迁移说明（`amended` → `superseded`、`expired` → `repealed`）。

**认不出的时效性返回 None，不默认成 effective。**
默认成有效等于"不认识的都当能引用"，方向反了。

### 二、导入时就要写对，不能靠事后修

`DocumentInput` 增加 `effect_status` 字段；采集侧从官方时效性翻译后传入；
导入器用它写**法规主表**和**条文版本表**两处——
检索过滤看的是版本表（`RegulationArticleVersion.effect_status`），
只改主表等于没改。

### 三、存量数据用核查脚本修，并清理索引

`scripts/audit_validity.py`：

1. 读采集留下的 sidecar，拿到官方时效性
2. 与库里逐条比对，打印差异（默认不写库，加 `--apply` 才写）
3. 改数据库（主表 + 版本表）
4. 同步向量库 payload，并**把不可引用的点从索引里删掉**

第 4 步用 `must_not` 白名单（而不是列举黑名单）：
黑名单会漏——`not_yet_effective` 这类状态不容易被想到。
用白名单则天然与检索过滤口径一致：检索只认 `CITABLE_EFFECT_STATUSES`，
索引里就不该留别的东西。

**为什么用"删点"而不是全量重建**：重建要 20 多分钟且要重算全部向量，
而这一步只是把不该出现的条目移除，删点几秒钟完成。

## 后果

- 修复后：222 份有效、45 份已废止、29 份已被替代、1 份尚未生效。
- 索引从 7109 条降到 5299 条（清掉 1810 条不可引用条文）。
- 10 个常见问题、50 条引用实测：**0 条不可引用状态**。
  问增值税已改引《增值税法》与《实施条例》，不再引《增值税暂行条例》。
- 新增测试 14 项（映射表、白名单、导入传播、废止法规不进索引）。

## 已知限制

- **106 份法规没有官方时效性记录**（主要是早期从旧项目导入的一批，
  采集时没有留下时效性字段）。它们仍按"现行有效"处理，
  需要补一次官方时效性查询才能确认。
- **"旧版本 vs 新版本"的互相替代没有自动识别**：
  例如库里有《企业会计准则第30号》的 2014 版和 2026 版，两版都在，
  2014 版没有被标成 `superseded`。目前只有官方明确标"已修改/废止"的才会被处理。
- **不知道确切的废止日期**，所以没有写 `valid_to`，
  "按某一天的时点查询"暂时无法还原历史版本。

## 补充约定：官方未标时效性的文件怎么处理

官方政策法规库并不给每份文件都标生效与失效日期。对这类文件：

1. **先补查官方，再退回正文。** 先逐份打开官方详情页读取时效性；官方确实没有的，
   从正文里的"执行期限为 X 至 Y""执行至 Y"推断 `valid_to`。
2. **执行期限届满不等于废止。** 它是时间区间问题，写进版本的 `valid_to`，
   不把文件整体判成"已废止"。
3. **时点过滤必须长期开启。** 检索时按问题时点过滤版本区间，否则历史口径会混进答案。

## 补充约定：valid_to 写在条文版本上

同一部法规的不同条文可能在不同时间失效，所以：

1. **时效区间只认条文版本上的 `valid_from` / `valid_to`**，法规主表上的失效日期不作准。
2. 主表字段仅作展示与检索辅助；判断"这条能不能引用"一律走版本区间。
